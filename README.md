# 霜藍週報｜測試版使用說明

## 這是什麼

這是獨立網頁測試版，配合 Google Sheets 使用。它目前指向「ATM任務追蹤系統資料庫－週報測試副本」，不是正式資料表。**請先在副本測試完整流程，不要立即切換正式資料表。**

測試副本：
https://docs.google.com/spreadsheets/d/1qQPtVhl2lmQyu_AHvfY-s6i2vst2DgENL6pMwc7JeRo/edit

副本包含複製時的原系統案件，請先在 Google 雲端硬碟確認副本的「共用」設定，確保只有你允許的人可以存取。副本保留原有四個雜事工作表，新增三個週報專用工作表：`週報_專案`、`週報_紀錄`、`週報_歷史`。網頁讀取 `案件總表`、`子項目清單`，但不寫入這兩個來源工作表。

## 第一步：建立獨立 GitHub 儲存庫

1. 解壓縮本檔，將資料夾內的檔案放到一個**新的** GitHub 儲存庫根目錄。保留 `index.html`、`app.js`、`styles.css`、`config.js`、`xlsx.full.min.js`、兩張 `jpg`、授權與說明檔案。不要上傳測試腳本或自己的機密資料。
2. 在儲存庫的 **Settings → Pages** 選擇 **Deploy from a branch**，再選擇放有上述檔案的 branch（例如 `main`）和 `/ (root)`，儲存。
3. 等待 GitHub Pages 建立網址，再使用該 HTTPS 網址開啟。網址的網域建議與既有雜事系統相同，即 `pppxd828-dotcom.github.io`；實際路徑取決於你替新儲存庫取的名稱。
4. 不要以雙擊 `index.html` 的 `file://` 方式驗證 Google 登入；Google OAuth 需要允許的網站來源。

GitHub Pages 的程式檔案可能公開。`config.js` 中的 OAuth client ID 與試算表 ID 是識別碼，不是密碼；**試算表仍需自行設定私人共用權限**。絕不可將 Google 密碼、OAuth client secret 或 API key 放進儲存庫。

## 第二步：確認 Google 登入

- `config.js` 預設沿用你提供的雜事系統中的 OAuth client ID，並指向測試副本。
- 在 Google Cloud 的 OAuth 網頁應用程式設定中，確認「授權的 JavaScript 來源」包含 `https://pppxd828-dotcom.github.io`。如果先前網站能登入，通常可沿用同來源，但仍需實際驗證。
- 使用有權存取測試副本的 Google 帳號登入。若 OAuth 同意畫面仍處於測試狀態，請確認該帳號是允許的測試使用者。若出現 `origin_mismatch`、權限不足或同意畫面錯誤，先檢查設定，不要關閉安全機制。
- 網頁向 Google 要求 `spreadsheets` 權限。這個權限的範圍不是只限於這一份表，而是涵蓋該帳號可存取的試算表；請確認你願意授權後再登入。
- 權杖只保留在目前網頁記憶體，不寫入程式或試算表。重新開啟、過期或登出後可能需要重新授權。網路或儲存失敗時，請先按「重新讀取」，確認資料是否已寫入，再決定是否重試，避免重複。

## 第三步：以副本試操作

1. 登入後到「專案管理」，檢查五個初始專案，自己補入需求號、預設處理人及里程碑。時程支援文字精度，例如 `116年6月` 或 `116年6月15日`；不會補猜日期。
2. 在「工作紀錄」新增紀錄，或貼上 Gemini 的 JSON。可先按「複製 JSON 整理指令」，把指令與日常紀錄交給 Gemini。
3. 「讀取雜事系統」會從副本的案件資料與子項目讀取。選取沒有變更時間的子項目，即表示由你確認本週相關。來源中的廠商或外部人員會保留，內部處理人仍須指定。
4. 「匯入 ATM Excel」只接受一個工作表的 `.xlsx` 或 `.xls`。核對欄位對應、勾選案件，在確認畫面補日期與處理人。整份來源檔不會被修改。
5. 在紀錄清單**逐筆勾選**本週要給長官看的事項。未勾選紀錄不會送進週報 Prompt。
6. 到「產生週報」確認異常分組、補足影響、確認架構變更及任何時程衝突。異常與確認正常台數分別輸入；其他尚未確認設備不會自動算為正常。
7. 編輯各區塊並按「複製 Prompt」，到 Gemini 等 AI 工具貼上。AI 有支援才會產出可下載 Word，否則請使用其提供的兩欄表格。
8. 同週歷史保存最後一次成功複製並寫入的版本。若自動複製或雲端儲存失敗，畫面會提示；請檢查是否真正保存。

## 資料與已知限制

- 這一版尚未在你的實際 GitHub Pages 網址完成真人 Google 登入測試；已使用模擬 Google 服務測試主要流程，並以 Google Drive 工具在副本測試基本讀寫。**不應視為已完成正式環境驗收。**
- 同一時間請只在一個分頁或裝置修改資料。網頁會檢查讀取版本，減少覆寫風險，但 Google Sheets 並未提供本工具完整的多裝置交易鎖，無法保證兩個裝置同時提交完全不衝突。
- 專案或單筆紀錄刪除會清空週報專用工作表中的對應資料；刪除專案也會刪除該專案的歷史 Prompt 區塊。Google Sheets 本身可能保留版本歷史，不能保證從 Google 的所有版本中永久抹除。原始雜事案件和原始 Excel 不會隨週報刪除。
- 共通指令不應手動放入特定專案的內容；否則刪除該專案時，系統無法保證辨識並清理你自由輸入在共通區塊中的文字。
- 本版的相似專案、類似異常和架構變更推薦以文字規則為基礎，不是 AI 判斷，可能誤判或漏判，請自行確認。已確認日期不明的歷程及子項目是否屬於本週。
- Excel 依第一列標題進行欄位對應；未提供欄位可在匯入確認時補充。若整個檔案包含多個工作表，會停止並請你整理為單一工作表。
- 一個試算表儲存格有長度限制。非常長的歷史 Prompt 可能無法保存；此時應保留畫面提示、縮短內容後重試。
- 部分異常判斷與預計時程必須人工確認，網頁不會自行判斷帳務是否受影響，也不會猜測未知數量、日期或專業事實。

## 關於正式 Sheet

目前不要把 `config.js` 改到正式 Sheet。要切換前，先在測試副本完成登入、案件匯入、Excel、週報、歷史、移除專案等驗收；然後再另行規劃如何在正式 Sheet 新增三個專用工作表並備份。直接把 ID 改成原 Sheet 而沒有建立所需工作表，網頁會讀取失敗。
